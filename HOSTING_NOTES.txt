ZeroCard — заливка (мультиязычные поддиректории + пре-рендер блога)
===================================================================

Структура dist:
  index.html              -> RU главная (/)
  en|de|es|pt|it|fr/index.html -> главные на языках (/en, /de, /es, /pt, /it, /fr)
  blog/index.html         -> RU блог (/blog)
  en|de|es|pt|it|fr/blog/index.html -> блог на языках (/en/blog и т.д.)
  blog/<slug>/index.html            -> RU статьи (готовый HTML)
  <lang>/blog/<slug>/index.html     -> статьи на языках
  assets/, sitemap.xml, robots.txt, .htaccess, _redirects

Каждая языковая страница (главная, индекс блога, статья) — ГОТОВЫЙ HTML
на своём языке: заголовки, текст, meta, canonical, hreflang, Schema.org.
Краулеры сразу видят контент.

Заливка
-------
Всё содержимое dist в корень сайта (public_html), включая подпапки
en/ de/ es/ pt/ blog/ и скрытые .htaccess и _redirects.

Статьи в репозитории (основной способ)
-------------------------------------
Статьи лежат в src/content/blog/<язык>/<slug>.md (Markdown + шапка с title,
description, date, category, order). Они ВСЕГДА попадают в пре-рендер,
sitemap и блок «Гайды» на главной, даже если Supabase недоступен при сборке.
Чтобы добавить статью: положи новый .md в нужную папку и пересобери.
Ссылки внутри статей: [текст](/blog/slug) для своих, полные URL для внешних.
Поле "audience: eu" в шапке статьи: вместо реферального блока pionex.com
показывается блок Webot EU (для читателей из ЕС после MiCA).

ВАЖНО про блог из Supabase (динамический контент)
-------------------------------------------------
Если Supabase недоступен в момент сборки (так было раньше: сборка шла в
окружении без доступа к базе), статьи из базы в HTML не попадут, а блог
покажет только статьи из репозитория. Проверь в логе сборки строку
"blog posts: N from repo + M from Supabase".

Статьи берутся из Supabase и пре-рендерятся В МОМЕНТ СБОРКИ. Значит:
  - Все статьи, что есть в базе на момент `npm run build:ssg`, попадают
    в статический HTML (лучший вариант для поиска).
  - Статьи, добавленные ПОСЛЕ сборки, будут работать как SPA (клиентский
    рендер) и попадут в пре-рендер/sitemap только после следующей сборки.
  => Пересобирай (`npm run build:ssg`) и перезаливай после публикации
     новых статей, либо повесь это на CI/крон после автогенерации.

Пересборка одной командой (на машине с доступом в интернет):
  npm install
  npm run build:ssg
(делает: sitemap -> client build -> SSR build -> prerender -> чистит dist-server)

Apache (REG.RU, Timeweb): .htaccess лежит в dist (скрытый файл!) и должен
заменить старый. Адреса без слеша на конце: /blog/slug. Со слешем и с
/index.html идёт 301 на чистый адрес. Проверено на Apache 2.4.
Старый .htaccess на хостинге отдавал 403 на папки статей.
  - /de, /de/blog, /de/blog/<slug> отдаются как готовые файлы
  - несуществующие статьи -> индекс блога языка -> дальше SPA
  - старые /?lang=de -> 301 на /de
Nginx / Netlify: см. _redirects и правила try_files (как для главных).

Проверка на СТЕЙДЖИНГЕ до прода (обязательно)
--------------------------------------------
  1. /de, /en, /es, /pt, /it, /fr — исходник страницы: <html lang="xx"> и текст на языке.
  2. /de/blog — открывается индекс блога на немецком.
  3. Любая статья /de/blog/<slug> — в исходнике заголовок и текст статьи,
     og:type=article, Article-разметка.
  4. F5 на любой из этих страниц не даёт 404.
  5. sitemap.xml содержит /, /en.., /blog, /en/blog.. и статьи.

После заливки добавь sitemap.xml в Google Search Console и Яндекс.Вебмастер.
Индексация новых языков/страниц — недели-месяцы.

AI-поиск и IndexNow
-------------------
- robots.txt явно разрешает AI-ботов (OpenAI, Anthropic, Perplexity, Google,
  Apple, Meta, YandexAdditional). Закрыт только /blog/admin.
- При сборке генерируются /llms.txt, /llms-full.txt и markdown-версия каждой
  статьи (URL статьи + .md). Ничего руками править не нужно.
- IndexNow: файл-ключ 8049633624651009799fdbe839982dd9.txt лежит в корне dist.
  После заливки новой сборки запусти:  npm run indexnow
  (отправит все URL из sitemap в Bing и Яндекс).

PREVIEW IN X / TELEGRAM / VK
- Each language has its own preview image: public/og/zerocard-<lang>-v4.jpg (1200x630 JPEG, ~70 KB).
- Articles use the image of their language. Source template: scratchpad script make.mjs (rendered HTML).
- To change the image later, save it under a NEW name (-v5.jpg) and update ogImage in
  scripts/prerender.mjs and ogImageFor in src/pages/Index.tsx. X caches previews by URL for about a week,
  a new file name forces a fresh fetch.
- twitter:site was removed: @zerocard is not the project's account. Add your own handle there if you get one.

LANGUAGE AUTO-SELECT
- Script at the top of index.html <head>. On /, /blog and /about (Russian hub pages) a first-time visitor
  goes to the browser language: de/es/pt/it/fr/en. Russian and CIS languages stay on Russian,
  any other language goes to /en.
- Articles are never redirected (the visitor picked that exact page, usually from search).
- Bots and link-preview crawlers are never redirected, so Google/Yandex still index the Russian pages.
- Choosing a language in the switcher sets cookie zc_lang for a year; that choice always wins.
- To open the Russian root without redirect for testing: https://zerocard.pro/?stay
